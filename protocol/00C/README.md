# 步骤00-C：全局执行规则冻结摘要

版本：2026.09.19-r1

本文件冻结全流程的 A/B 边界、五本账、A冻结包、B交付、论证蓝图、写作/图表质量控制、断点续跑、状态机和冻结失效规则。本步不训练模型、不创建论文 Word。

## 1. A/B 边界
- **A步骤**：只做计算、建模、验证、代码与结果落盘、证据核验和冻结；不得创建或重建论文 Word。
- **B步骤**：只使用已经通过的对应 A 冻结包 + 当前唯一母稿 LATEST_WORD 做增量修改；不得训练、调参、重新选模或擅自改写冻结结果。
- 如 B 发现 A 的真实结果不足以支撑文字，必须降调表述、修改论证蓝图或回退对应 A；不得在 B 中补跑模型。

## 2. 五本账
1. 版本总账：数据、代码、配置、环境、run、冻结包、Word、图表等版本链。
2. 证据与问题总账：证据状态、P0/P1/P2、异常、失败、未决问题及影响范围。
3. 结果与公式总账：正式结果、指标、核心公式、适用口径及证据引用。
4. 图表总账：图/表文件、图注、支撑论点、来源、run_id、SHA、Word位置。
5. 引用总账：文献/官方资料/数据来源、引用键、支撑论点和Word位置。

B阶段只更新本步变更直接影响的条目，不全表重写。

## 3. A冻结包
每个后续 A 步骤使用统一模板：
run_id、代码/数据/配置/环境/随机种子、参数、真实结果、验证证据、异常/失败、B所需数据与结论、未解决问题、冻结摘要与SHA。
A未通过时不得产生“passed”冻结包供B使用。

## 4. B交付
每个 B 步骤必须交付：
- 新版 Word（建立在唯一母稿上的增量修改）
- 本步变更单
- 受影响账目
- 图表文件/图注（如有）
B禁止抽取纯文本后重新生成整份 Word，禁止无依据改写 A 结果。

## 5. 本问论证蓝图
顺序固定为逻辑字段、结构表现可随题意自适应：
题目交付 → 核心矛盾 → 基线及不足 → 方法选择理由 → 1–3个关键改进 → 主指标/公平口径 → 关键图表 → 核心结论 → 下一问接口。
真实结果不支持时必须降调或修改蓝图。

## 6. 写作与图表质量
模型原理只写本题真正使用的部分；核心公式必须参与求解、指标或解释。
“有效、提升、稳定、鲁棒、优于、显著、改善、更好”等表述必须绑定数字、区间、图表或验证证据。
图随文走；表能清楚表达时优先表。禁止无关2×2/2×3总览、仪表盘、卡片、渐变阴影、PPT风。所有正式图表必须可追溯到数据版本和run_id。

## 7. 断点与状态机
继承00-B低负载断点协议。单步过重时只在自然批次结束暂停；保存checkpoint、完成/未完成清单和RESUME_TOKEN。暂停时 PASS_TOKEN=无，NEXT_ALLOWED保持当前步骤。
每步开头必须核验 CURRENT_ALLOWED_STEP、LAST_PASS_TOKEN、LATEST_WORD、LATEST_FREEZE_PACKAGE、OPEN_P0、NEXT_ALLOWED。非法跳步立即停止。

## 8. 冻结失效
步骤13后，如果原始/派生数据、代码、模型、关键参数或核心结果发生实质变化，则受影响冻结包及依赖它的Word状态失效。必须回退到最早受影响A步骤，重新执行步骤13及所有依赖后续步骤。

机器可读规则见 global_rules.json；空账表、模板与流程状态卡均位于 protocol/00C/。
